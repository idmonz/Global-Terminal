# Codex Workflow

## Phase Loop

1. Read the durable goal, roadmap, previous final report, and active prompt.
2. Run the repository preflight and write the baseline report.
3. Select exactly one vertical phase from evidence.
4. Write product, API/data, visual, safety, and release acceptance contracts.
5. Inspect existing Streamlit pages, `lib` engines, API routes, and web components.
6. Add focused failing tests, then implement the complete user journey.
7. Run narrow checks, full Python/web gates, visual QA, and release inspection.
8. Update the benchmark scorecard from observed evidence.
9. Write the final report and evidence-based next goal.

## Evidence Hierarchy

Prefer current code, test output, API payloads, screenshots, and release contents over earlier narrative claims. A contract or fixture alone does not prove product parity. A nonblank renderer alone does not prove benchmark quality.

## Safety And Data Truth

Every major row or panel must expose source, freshness/time, state, caveat, and data gap. Keep research informational and read-only. Never add execution or personalized recommendation behavior.

## External References

Use external code and products through the clean-room skill. Do not interpret mechanical line inventory as semantic review or license clearance.

Outputs are research calculations and information displays only. They are not investment advice, trading recommendations, trade approvals, hedging instructions, broker actions, autonomous actions, or execution instructions.
